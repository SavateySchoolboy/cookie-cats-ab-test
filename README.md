# A/B-тест Cookie Cats: перенос первых ворот с 30-го на 40-й уровень

Учебный проект по анализу A/B-теста на данных мобильной игры Cookie Cats.
Задача: понять, стоит ли переносить первые «ворота» (момент, где игроку предлагают подождать или заплатить) с 30-го уровня на 40-й.

**Вывод: не запускать вариант с воротами на 40-м уровне, оставить ворота на 30-м.**
Главная метрика (удержание на 7-й день) в тестовой группе значимо ниже.

## Данные

Файл `cookie_cats.csv`, около 90 тысяч игроков.

| Столбец | Описание |
|---|---|
| `userid` | идентификатор игрока |
| `version` | группа: `gate_30` (control) или `gate_40` (test) |
| `sum_gamerounds` | число сыгранных раундов за первые 14 дней |
| `retention_1` | вернулся ли игрок на следующий день (True/False) |
| `retention_7` | вернулся ли игрок через 7 дней (True/False) |

Один выброс (игрок с 49 854 раундами) исключён как подозрение на бота.
Данных о выручке и платящих игроках в наборе нет.

## Дизайн анализа

- **Гипотеза:** более поздние ворота улучшат удержание игроков.
- **Главная метрика:** доля вернувшихся на 7-й день (`retention_7`).
- **Вторичные метрики:** доля вернувшихся на 1-й день, доля игроков с 30–40 раундами (диагностика механизма).
- **Защитная метрика:** число сыгранных раундов (медиана и распределение), не должна ухудшиться.
- **Правила:** двусторонние тесты, α = 0.05, порог SRM = 0.001.
- **Правило решения:** запускаем test, только если `retention_7` значимо вырос и защитная метрика не ухудшилась.

## Что сделано в ноутбуке

1. Проверка SRM (честность разбиения на группы) критерием χ².
2. Сравнение долей `retention_1` и `retention_7`: z-тест для двух пропорций, доверительные интервалы разницы.
3. Пересчёт потерь удержания на 100 000 новых игроков.
4. Защитная метрика: критерий Манна-Уитни, бутстрэп-интервал для разницы медиан, t-тест по среднему для сравнения.
5. Дополнительный анализ среди вернувшихся на 7-й день (с оговоркой про смещение отбора).
6. Доля игроков с 30–40 раундами и график распределения по раундам.
7. Мощность и MDE для двух метрик, обратная задача (сколько игроков нужно для заметной разницы).

## Основные результаты

| Метрика | control | test | Разница | Значимость |
|---|---|---|---|---|
| retention_7 | 19.0% | 18.2% | −0.8 п.п. (интервал от −1.3 до −0.3) | значимо, p ≈ 0.0016 |
| retention_1 | 44.8% | 44.2% | −0.6 п.п. (интервал от −1.2 до +0.06) | не значимо, p ≈ 0.07 |
| Число раундов (все игроки) | медиана 17 | медиана 16 | средние 51.34 и 51.30 | Манн-Уитни p ≈ 0.051, пограничный результат |
| Доля игроков с 30–40 раундами | 7.5% | 6.6% | −0.9 п.п. | значимо, p < 0.001 |

- В пересчёте на 100 000 новых игроков к 7-му дню вернулось бы на 310–1326 игроков меньше (лучшая оценка около 818).
- SRM не обнаружен: p = 0.0086 больше порога 0.001, но значение близко к границе.
- MDE для `retention_7` около 0.73 п.п., для `retention_1` около 0.93 п.п. (мощность 0.8).
- Чтобы заметить падение на 0.5 п.п., нужно около 95 700 игроков на группу по `retention_7` и около 155 100 по `retention_1`. В тесте было около 45 000 на группу.

## Ограничения

- Нет данных о выручке: ворота влияют на монетизацию, решение только по удержанию неполное.
- Анализ среди вернувшихся на 7-й день нельзя читать как причинный (смещение отбора).
- Результат по защитной метрике пограничный (p ≈ 0.051), разница очень мала.
- Один эксперимент, повторить результат на другой выборке не удалось.

## Как запустить

Нужен Python 3.9+ и библиотеки:

```bash
pip install pandas numpy scipy statsmodels seaborn matplotlib jupyter
```

Положите `cookie_cats.csv` рядом с ноутбуком и откройте `abtest_analys.ipynb` в Jupyter или VS Code. Ячейки выполняются сверху вниз. Бутстрэп использует `random_state=42`, поэтому результаты воспроизводятся.
